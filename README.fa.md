# اندرون

[English](README.md)

اندرون یک شبکهٔ اجتماعی متنی و دعوتی است که با Django ساخته می‌شود. همهٔ اجزای آن روی یک سرور اجرا می‌شود و به هیچ سرویس بیرونی وابسته نیست؛ به همین دلیل، وقتی دسترسی به اینترنت بین‌الملل قطع می‌شود، روی شبکهٔ داخلی همچنان کار می‌کند.

نام پروژه یادآور اندرونی خانه‌های قدیمی ایرانی است؛ بخش درونی و خصوصی خانه.

> **وضعیت:** مراحل اولیهٔ توسعه (نسخهٔ ۱، فاز ۱٫۱: حساب‌های کاربری). هنوز برای کاربر واقعی یا استقرار در محیط عملیاتی آماده نیست.

## چرا اندرون؟

در قطعی‌های سراسری اینترنت در ایران، مانند آبان ۱۳۹۸ و خرداد ۱۴۰۴، ارتباط با اینترنت بین‌الملل قطع می‌شود، اما سرورهای داخل کشور از طریق شبکهٔ داخلی همچنان در دسترس‌اند. سرویس‌هایی که به تأیید ایمیل یا پیامک، CDNهای خارجی، فونت‌های تحت وب یا APIهای خارجی وابسته‌اند، پیش از بقیه از کار می‌افتند. اندرون به هیچ‌یک از این‌ها تکیه نمی‌کند: حساب کاربری فقط نام کاربری و رمز عبور است، همهٔ فایل‌ها از خود برنامه ارائه می‌شود و عضویت به‌جای تأیید ایمیل، با دعوت انجام می‌شود.

## وضعیت پیاده‌سازی

| بخش | وضعیت |
| --- | --- |
| راه‌اندازی پروژه؛ خواندن تنظیمات از متغیرهای محیطی، الزامی‌بودن `SECRET_KEY` و خاموش‌بودن `DEBUG` به‌طور پیش‌فرض | انجام‌شده |
| مدل کاربر سفارشی: ورود با نام کاربری، محدود به الگوی `[a-z0-9_]{3,20}` و ذخیره با حروف کوچک | انجام‌شده |
| پنل مدیریت برای مدل کاربر سفارشی | انجام‌شده |
| ورود، خروج و تغییر رمز عبور | گام بعدی |
| ثبت‌نام فقط با دعوت‌نامه و با تأیید عضو دعوت‌کننده | گام بعدی |
| پروفایل، پست متنی، نظر، پسند، دنبال‌کردن، فید، جست‌وجو و اعلان‌ها | برنامهٔ نسخهٔ ۱ |
| پیام خصوصی و گروهی، سپس رمزنگاری سرتاسری | برنامهٔ نسخهٔ ۲ |

برنامهٔ کامل، همراه با معیار پایان هر فاز، در [ROADMAP.md](ROADMAP.md) آمده است.

## اصول طراحی

- **بدون ایمیل و شمارهٔ تلفن.** حساب کاربری فقط یک نام کاربری و یک رمز عبور است و دعوت‌نامه جای تأیید ایمیل را می‌گیرد.
- **بدون سرویس بیرونی.** نه فونت خارجی، نه CDN، نه ابزار تحلیل و نه API بیرونی؛ همه‌چیز از همان سرور ارائه می‌شود.
- **نام کاربری سخت‌گیرانه.** فقط حروف کوچک لاتین، عدد و زیرخط مجاز است؛ این قاعده جلوی نویسه‌های مشابه فارسی و عربی را می‌گیرد.
- **پیش‌فرض امن.** بدون `SECRET_KEY` برنامه اجرا نمی‌شود و `DEBUG` تا زمانی که صریحاً روشن نشود، خاموش می‌ماند.
- **فقط متن در نسخهٔ ۱.** نبودِ بارگذاری فایل یعنی نه ذخیره‌سازی رسانه، نه پردازش تصویر و سطح حملهٔ کوچک‌تر.

## فناوری‌ها

- Python 3.12 و Django 6.1
- SQLite در محیط توسعه؛ PostgreSQL برای محیط عملیاتی (برنامه‌ریزی‌شده)
- python-dotenv برای پیکربندی
- Docker برای استقرار (برنامه‌ریزی‌شده)

## راه‌اندازی

پیش‌نیاز: Python 3.12

در macOS و لینوکس:

```bash
git clone https://github.com/sepehrkhasto/andarun.git
cd andarun
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

در ویندوز (PowerShell):

```powershell
git clone https://github.com/sepehrkhasto/andarun.git
cd andarun
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

یک کلید امن بسازید و آن را در فایل `.env` به‌جای `change-me` قرار دهید:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

سپس پایگاه داده و حساب مدیر را بسازید و سرور توسعه را اجرا کنید:

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

پنل مدیریت در نشانی <http://127.0.0.1:8000/admin/> در دسترس است.

## پیکربندی

همهٔ تنظیمات از متغیرهای محیطی خوانده می‌شود و در محیط توسعه از فایل `.env` بارگذاری می‌شود.

| متغیر | الزامی | مقدار پیش‌فرض | توضیح |
| --- | --- | --- | --- |
| `SECRET_KEY` | بله | ندارد | بدون آن برنامه اجرا نمی‌شود. |
| `DEBUG` | خیر | `False` | با مقدار `1`، `true` یا `yes` روشن می‌شود. |
| `ALLOWED_HOSTS` | خیر | خالی | با کاما جدا می‌شود؛ مثلاً `localhost,127.0.0.1` |

## آزمون‌ها

```bash

```

هنوز آزمونی نوشته نشده است. در نقشهٔ راه، آزمون‌های هر فاز جزو معیار پایان همان فاز است و این کار از بخش حساب‌های کاربری شروع می‌شود.
